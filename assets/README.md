# GeoGuard drone model

This directory contains a small, original low-poly quadcopter. It is deliberately generated
inside the repository, so the demo does not depend on a model downloaded under uncertain
terms.

## Build

Run from the repository root:

```sh
node assets/build-drone-model.mjs
```

The converter uses only Node.js built-ins. It parses OBJ vertices and polygon faces,
triangulates faces, calculates smooth vertex normals, uses 16-bit indexed geometry, aligns
binary sections to four bytes, and writes a glTF 2.0 binary container. The output is
`assets/processed/geoguard-drone.glb`.

The source coordinate system is right-handed, Y-up, measured in model units, with the nose
pointing along +X. In Cesium, place it with an ENU fixed frame, apply the telemetry heading
around the local up axis, then apply a constant model-axis correction only if the consuming
entity API expects a different forward axis. Scale it to the desired on-screen meter size.

File sizes are updated after generation; the committed GLB can be regenerated byte-for-byte
from the source OBJ and script.

| Stage | File | Size |
|---|---|---:|
| Original | `raw/geoguard-drone.obj` | 1,655 bytes |
| Processed | `processed/geoguard-drone.glb` | 2,172 bytes |

The GLB is slightly larger than this deliberately tiny text OBJ because it embeds normals,
material metadata, scene structure, and a complete binary container. For real textured
models, the same single-file GLB packaging removes external `.bin`/texture requests; this
toy asset demonstrates the reproducible conversion and axis/normal handling rather than a
misleading compression claim.
