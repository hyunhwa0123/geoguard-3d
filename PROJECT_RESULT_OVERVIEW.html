HOW THE SPATIAL CHECK WORKS

드론이 위험구역 안에 있는지는 어떻게 계산할까?

핵심은 수평 위치(X·Y)와 고도(Z)를 따로 확인하는 것입니다. 위험구역은 2D Polygon이고, 드론은 고도를 포함한 PointZ입니다.

01 · POINTZ입력 좌표를 하나의 3D 점으로

ST_MakePoint(longitude, latitude, altitude)에 SRID 4326을 지정합니다. 저장 형식은 geometry(PointZ, 4326)입니다.

02 · ALTITUDE고도는 별도 숫자 비교

altitude BETWEEN min_altitude AND max_altitude를 먼저 적용합니다. 지도상 내부여도 제한 고도 밖이면 SAFE입니다.

03 · DISTANCE미터 단위 후보를 먼저 축소

ST_DWithin(...::geography, 200.0)으로 200m 이내 구역만 남기고, ST_Distance로 실제 거리를 계산합니다.

04 · COVER경계선까지 내부로 처리

ST_Covers(boundary, point)가 참이면 DANGER입니다. ST_Contains와 달리 경계선 위의 점도 포함합니다.

05 · MULTIPLE ZONES겹치면 가장 위험한 하나를 선택

DANGER를 WARNING보다 먼저, 그다음 거리와 구역 ID 순으로 정렬해 첫 결과 하나를 선택합니다.

06 · TRANSACTION판정값과 위치를 함께 저장

telemetry에 상태를 저장하고 WARNING/DANGER만 risk_event를 만듭니다. DB 커밋 후 같은 결과를 WebSocket으로 보냅니다.

!

실시간 화면의 최종 판정자는 백엔드입니다. 프런트엔드의 TypeScript 공간 계산은 백엔드가 끊겼을 때 표시하는 오프라인 데모용 보조 로직입니다. 실제 DRONE-LIVE-001 상태는 RiskRepository.java의 PostGIS 결과를 그대로 사용합니다.

Parallel Seq Scan이 BitmapAnd로 바뀌면 왜 빨라질까?

결론: 테이블 전체를 나눠 훑던 방식에서, 시간과 위치 인덱스가 찾아낸 후보의 교집합만 원본 테이블에서 읽는 방식으로 바뀌었기 때문입니다.

06 / GUIDE & BOUNDARY

용어와 현재 범위

낯선 GIS 용어는 펼쳐서 확인할 수 있습니다. 오른쪽에는 포트폴리오를 과장하지 않기 위한 현재 한계를 명시했습니다.

PostGIS

PostgreSQL에 공간 자료형과 공간 함수, 공간 인덱스를 추가하는 확장입니다. 이 프로젝트에서는 Polygon과 PointZ 저장, 포함·거리·BBOX 검색에 사용합니다.

PointZ · Polygon

PointZ는 경도(X), 위도(Y), 고도(Z)를 가진 3차원 점입니다. Polygon은 여러 좌표로 둘러싼 위험구역의 수평 경계입니다.

EPSG:4326

GPS에서 흔히 쓰는 WGS84 경도·위도 좌표계 식별자입니다. 시뮬레이터, API, DB, Cesium 간 좌표 기준을 맞춥니다.

BBOX

서·남·동·북 네 값으로 만든 사각 검색 영역입니다. 현재 지도에 보이는 범위 안의 위치만 조회할 때 사용합니다.

GiST

PostgreSQL의 범용 트리 인덱스 구조입니다. PostGIS 공간 객체의 겹침 후보를 빠르게 줄여 전체 행을 훑는 일을 피합니다.

GeoJSON · GLB · WebSocket

GeoJSON은 위험구역 같은 공간 데이터를 JSON으로 표현합니다. GLB는 glTF 기반 3D 모델 단일 파일입니다. WebSocket은 연결을 유지해 서버가 새 위치를 즉시 밀어주는 통신 방식입니다.

HONEST BOUNDARY

현재 구현의 한계

  • 위험구역과 비행 위치는 실제 항공 데이터가 아닌 합성 데이터입니다.
  • 실시간 WebSocket은 단일 백엔드 프로세스 메모리 세션 기준이며 메시지 브로커는 없습니다.
  • 인증·권한, 드론 장비 프로토콜, 장애 재처리 큐는 하루 프로젝트 범위에서 제외했습니다.
  • 동적 순환 경로의 내부 4점 방식은 현재 직사각형/볼록 다각형 데모 구역에 맞춘 구현입니다.
  • 10만 건 성능 수치는 한 장비·각 1회 측정이라 운영 용량 보장을 뜻하지 않습니다.
